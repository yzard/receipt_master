# 商品名称与商品种类唯一性

## 规则

- 名称经过 Unicode NFKC 规范化，再去掉首尾空白、将连续空白合为一个空格。
- 英文字母 A–Z 大小写不区分；保留已有记录的显示拼写。
- 商品名称在用户的商品目录中唯一；商品种类在同一目录内全局唯一，父类不同也不能同名。
- SQLite 的 `product_name_name_uq`、`category_name_uq` 唯一索引提供最终保护；所有目录写入入口先规范化。
- 添加/改名商品种类遇到同名记录返回 HTTP 409，错误码 `duplicate_category_name`。
- 给票面名称指定商品名称、给商品指定种类时，同名表示复用已有记录，不创建重复记录。多个票面名称仍能关联同一个商品名称。
- Web、Android、iOS 的搜索输入框提示复用已有名称；添加/改名商品种类禁止重名，失败后保留输入框和编辑窗口。
- 草稿仍只保存收据自己的提议，确认前不会创建全局商品名称。

## 已有数据库的一次性处理

服务启动不执行迁移。运行独立脚本，覆盖管理员及 `users/*` 的收据库，不修改 `auth.sqlite`。

先停止 backend_api，然后运行：

```bash
python3 src/backend_api/tools/deduplicate_catalog.py \
  --data-dir /path/to/backend_api \
  --backup-dir /path/to/new-backup-directory
```

脚本在任何写入前检查所有收据库、备份每个待处理数据库。每个库在独占事务中完成：

1. 合并重复商品名称及商品种类：系统种类优先保留，其余优先保留关联较多的记录，ID 决定同等条件下的顺序。
2. 将票面名称映射、商品分类、明细分类、种类父节点指向保留的 ID。多个商品分类冲突时优先保留关联较多记录的明确分类，已有明确分类优先于未分类。
3. 统一已有草稿中的名称提议，保留草稿状态。
4. 添加唯一索引，检查外键和完整性，核对收据明细、图片及其他无关表内容未变化。
5. 数据发生变化时递增目录与收据版本，让已打开的编辑器重新加载。

重复运行没有待处理数据时不再修改。若发生约束或完整性错误，该库事务回滚，原始备份保留。schema 版本仍为 15。
