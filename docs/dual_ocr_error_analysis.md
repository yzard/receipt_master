# 双 OCR：哪些细节仍不准

基于 2026-09-17 串行版 24 张实测的原始双模型输出、解析结果、历史确认数据，并目视核对 6 张代表原图。没有重新运行模型，没有修改确认答案或评分。

## 先区分三层问题

1. **文字识别**：数字、汉字、名称、日期本身被读错或漏掉。
2. **解析与合并**：文字已经读对，但没有正确解释数量、税、折扣或多个时间。
3. **历史答案差异**：确认数据本身可能保留了旧错误或默认值。必须核对原图，不能为了提高分数直接改答案。

当前返回有效结构 24/24、总额一致 24/24、明细数一致 18/24、交易时间一致 18/24、全部评分字段一致 7/24。总额正确不代表商品明细正确。商品标准名/用户别名不参与现有评分，因此中文错字可能没有反映在这 17 张不完全一致的统计中，不能用严格通过率衡量中文准确率。

## C. 原图支持当前结果，但历史确认数据有疑点

完整编号、旧值与原图链接见 [人工核对清单](confirmed_data_manual_review.md)。

- **`e3843baa` 的上午/晚上**：原图两处都为 `08/23/26 09:32pm`，两个模型都正确读出。当前转换为晚上，确认数据却早 12 小时。这处时间差异不应直接认定为模型错误。
- **`d7f8ff6d` 的白菜重量**：原图为 `3.02 lb @ $0.58/lb`，金额 `$1.75`；当前识别与换算吻合。历史确认值却是数量 1、单位 ea、单价 `$1.75`。类似重量/件数表示差异还出现在 `e9ee06e0`、`5331c892`，需分别核图后处理。
- **`ca76c352` 的蓝莓名**：原图可辨为 `BLUEBERRIES`，PP 读对并被采用；历史确认值为 `BLUERRIES`。该名称差异实际上可能是纠正旧漏字。
- **`8572dcef` 的断笔 SKU**：已确认值与两个模型的输出都不一致，不应在没有足够图像或商品字典证据时指定其中一个必然正确。

以上只记录审计意见，**没有改写标准答案、数据库记录或本轮分数**。

## 接下来优先处理什么

1. 补 99 Ranch、Target 专用规则，以及 H Mart 促销说明排除/折扣处理；这些已有可读文字证据。
2. 对重复时间按交易区、付款区和底部打印区区分角色；相差几秒与相差年份不能使用同一种处理。
3. 双模型 SKU 不一致必须明确提示；结合商店 SKU 表，但不能仅因为金额相同就替换编号。
4. 对 `Spl/Sp1` 等已验证的促销标签混淆做有限容错，并保留原文和核对提示。
5. 独立核验历史确认数据；另建票面中文逐字标注，才能量化 PP-OCR 中文漏字及双模型共同错误。
