# 报表曲线的当前分类与图例

## 原因

报表后端原本就按请求查询 SQLite，并非读取预先保存的统计表。`line_effective_category` 优先使用商品名称当前关联的分类，再回退至收据明细的分类；商品优惠继承其对应商品。

旧曲线选项把分类与商品列成两个列表（Web 混在一个列表里），没有展示商品所属分类。因此已分类商品依然出现在单独的商品列表。打开选项时客户端还会使用此前加载的曲线数据。Web 也缺少图例，且取消一条曲线会改变其他线的颜色。

## 当前行为

- 每次趋势、汇总或明细请求都从当前数据库计算，不保存统计快照，不使用写操作的幂等响应缓存。
- 汇总中的商品分组与趋势中的商品曲线带有 `category_keys`，由本次查询的有效分类及分类树生成。汇总按顶层分类（或父类过滤时的子类）分组；趋势商品按其直接所属分类排列。
- 趋势始终返回数据库内全部商品种类，包括没有消费的分类、子类和未分类；空分类各时间点为零，并在 Web/Android/iOS 曲线选择中灰显禁用；切换到有消费的时间范围后即可选择。每个分类曲线汇总自己和所有后代的消费，父类/子类可独立开关，商品仅在直接所属分类下列出。总金额及汇总明细不会重复计入父子分类。
- 曲线选项先列分类合计，再在所属分类下显示商品；分类与商品曲线仍可分别开关。税费、整单优惠等仅作为分类，不作为商品。
- 有对应商品的优惠合并至该商品曲线，即使商品尚未设置商品名称，也使用对应商品的票面名称归组。
- 进入报表、打开曲线选择、选择时间点、刷新和回到前台都会重新请求统计。打开选项查询失败时不展示旧选项。
- Web 趋势刷新会触发当前周期汇总再次查询；同一周期范围也不会沿用旧汇总。移动端刷新同时查询趋势和本期/上期数据。
- 图例属于图表组件；只显示当前可见的曲线。标签区分“总金额”、“商品分类”和“商品”。曲线颜色按 key 确定，开关其他曲线不改变已有曲线颜色。

## 验证

- 历史收据只更新商品目录分类，保持收据明细旧分类不变：下一次趋势请求立即反映当前分类，金额不变，分类树筛选也生效。
- HTTP 使用相同 `request_key` 重复读取：新增确认收据、重新分类后均返回当前数据。
- 商品优惠在缺少商品名称时仍归组至原商品；整单优惠不会出现在商品曲线中。
- Web 和移动端检查：重新打开选项后商品处于最新分类，选择商品曲线后显示对应图例；Web 另检查线条与图例颜色一致、切换其他曲线后颜色稳定。

- 空数据库、无消费时间窗口和父子分类均完整提供曲线选项；Web 和 Android/iOS 共享组件验证独立开关不连带选择商品。

- 后端返回 `has_activity` 决定零消费禁用状态：购买与退款抵消后的净额为零仍可选择，只有没有非零明细的种类才禁用。

## 分类折叠和选项可见性

Web 原选择区高度限制为 240px，分类下所有商品默认展开，导致其他品类藏在内部滚动区。现在移除该限制，分类头部以响应式网格排列，随整个页面滚动。Web 和移动端均默认折叠每个分类的商品列表，点击箭头/商品数量展开或收起；分类勾选始终可见，展开操作不会修改任何曲线选择，收起后保留已选商品。没有商品的分类不显示展开按钮。

回归覆盖多分类、大量商品、默认折叠、独立展开与选择，以及收起后保留选中的商品曲线。

Web 与 Android/iOS 的顺序统一为：趋势图和图例 → 周期与曲线选择控件 → 分类选项或周期明细。调整曲线时图表始终位于选项上方。
