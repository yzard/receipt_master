# 按店铺选择提示词：实现与实测

日期：2026-09-17 UTC。当前部署 `vision-v7`。

## 已实现

- 未知店铺或没有专用模板的店铺：使用通用提示词。
- Logo 图像 Alias 确认店铺后：组合通用提示词与 Costco、SkyFoods 或 H Mart 专用规则。大小写、空白和标点不影响已登记名称的匹配，不用子串猜店铺。
- Costco 模板集中处理预扫描区、SKU/税码、优惠负号、商品关联、押金、退款及付款总额；SkyFoods 处理双语名称、已含优惠净价、重复商品与折扣索引；H Mart 处理完整名称及称重详情归属。
- 模板选择由结构化 `receipt_context.known_store` 驱动；不从 OCR 文字中解析店名。Logo 定位不附带收据模板。
- 每次识别记录模板名、版本及组合提示词 SHA256。API 仍只校验结构和关联、执行确定性换算，没有恢复商品文字解析器。

文件及新增模板的方法见 [后端说明](backend_ocr.md#商店提示词vision-v7)。客户端无需新增设置；原有收据未被批量修改。

## 程序验证

77 项 Rust 测试通过，包含已知店铺路由、未知店铺回退、正文提到别家商店不切换模板、参数验证、有效提示词哈希、Logo 匹配后整张多图请求选择 Costco 模板。总 Docker 构建通过，两个服务运行正常，APK 仍为 build 10025。

最终版本实测未知店铺的两张重叠照片：9 ms 接受后台任务，去重后保存四个商品与零税额，总额 14.00，查询保持响应。真实 Logo Alias 链路在第一轮模板版本通过；两轮使用相同的路由实现，最终回归测试也覆盖该顺序。此次未新增手机 UI，不涉及客户端数据迁移；未在 Linux 上执行原生 iOS 构建。

## 准确性：尚未证明整体改善

| 评测 | 原通用混合规则 v5 | 第一轮拆分 v6 | 最终组合 v7 |
| --- | --- | --- | --- |
| 17 张历史票据全字段通过 | 8/17 | 4/17 | 8/17 |
| 3 张近期问题票据关键项通过 | 1/3 | 0/3 | 0/3 |

第一轮重写通用规则产生回退，因此最终版恢复原通用规则的关键措辞，再组合商店规则。以上是同一组照片的单次评测，不能解释为稳定准确率；v7 的 17 张均提供了已知店名，v5 只给 Costco 提供店名，因此也不是只改变一处提示词的严格 A/B 实验。只提供店名，不把商品答案传给模型。

本次主要变化：

- `bbbfe093` 会员退款现在全字段通过，包括负数金额和税。
- `00c86447` 从通过变成多出一条明细；`e8698610`、`b38d62dd` 返回 HTTP 502，未接受无效结果。
- `3a8e3c19` 原本通过，本次两条优惠被识别成 +5.00，金额不符。
- `e6c62f11` 仍漏优惠并混淆商品/SKU；`6d9da1ec` 优惠名称及商品关联正确，但仍未标记已含优惠净价，导致重复扣减。
- H Mart 的 `5e4547ea` 仍把苹果的重量关联到 FAGE；其他历史样例仍有名称、时间和折扣错误。

所以本次完成的是**按店铺独立调优的能力**，没有完成“所有历史问题识别正确”的验收，也不能声称总体效果已经优于上一版。金额错误保留供确认，不通过改写标准答案、静默补金额或恢复 API 商品解析规则来掩盖。
