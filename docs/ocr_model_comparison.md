# 17 张真实票据：Unlimited-OCR 与 PP-OCRv6 medium

日期：2026-09-16。

## 结论

**当前实现下，不建议直接用 PP-OCRv6 medium 替换 Unlimited-OCR。** PP 的中文文字保真更好，但商户 Logo、`lb` 单位和票面异常字符影响后续解析，最终总额、重量和优惠结果更差。PP 值得进一步作为中文识别补充进行验证；本次没有实现混合识别，也没有切换 playground 模型。

这不是“PP 普遍不如 Unlimited”的结论：这是当前固定参数、现有 Qwen 结构化模型及后处理，在这 17 张个人收据上的对照结果。

## 数据与方法

原 12 张加新 5 张：00710190、00c86447、6fe7d01a、b38d62dd、e1be8ec6。所有原图均已保存并固定 SHA-256；逐张人工核对，使用相同答案。

每个模型每张图只运行一次，保留全部结果与失败。先分别采集真正的 OCR 输出，然后通过同一个生产 `pipeline::recognize`、同一个 Qwen3-4B-Instruct-2507、相同提示词/schema/temperature=0/8192 输出限制和业务规则，最后通过同一个 `jobs::merge` 评分。没有用用户 Alias 修正结果，没有写入真实票据数据库。

PP 使用 medium_det + medium_rec，PaddleOCR 3.7.0 / PaddlePaddle 3.3.0。按坐标将文字块还原为行，没有修正拼写或为 PP 增加专用业务规则。已核查典型金额行的排序，例如 2f083787 的商品名和金额正确排在同一行，错误仍出现在结构化/重量处理阶段。

## 比较结果

| 指标 | Unlimited-OCR | PP-OCRv6 medium |
| --- | ---: | ---: |
| 原始 OCR 完整英文商品名命中 | **52/56（92.9%）** | 50/56（89.3%） |
| 原始 OCR 完整中文商品名命中 | 15/29（51.7%） | **23/29（79.3%）** |
| 完成结构化并通过 schema 校验 | 16/17 | **17/17** |
| 总额正确 | **16/17** | 13/17 |
| 时间正确并正确转换 UTC | 15/17 | **16/17** |
| 商户名称正确 | **15/17** | 6/17 |
| 所有行金额、种类、优惠关联及行数符合 | **14/17** | 9/17 |
| 重量、数量、单价及行数符合 | **12/17** | 5/17 |
| 整张全部字段符合严格答案 | **4/17** | 0/17 |

指标解释：

- 原始名称命中要求整段商品名出现，忽略空格、大小写、全半角；相同商品买两份需要两次出现。遮挡无法辨认的名称不计入该项分母。这不是 OCR 字符准确率，也不证明名称与金额关联正确。
- 中文按票面字形比较，简繁差异也会计为不完全匹配。
- 结构化失败计入最终字段指标的失败；不是把失败样本排除后再算正确率。
- 0/17 表示每张至少有一个差异，不表示 17 张都完全读不出来。例如一张仅商户名丢失，也不能算整张全对。
- 重量和优惠指标是整张一致性检查，包含商品行数，不是单独的数字字符准确率。

## 具体差异

- **中文改善**：a730a1be 的“壇壇鄉豉香朝天椒”，PP 读对，Unlimited 读成“廣廣鄉 鼓香朝天椒”。多张“白菜苗”在 PP 中正确，Unlimited 中出现“白菜菇”。
- **中文仍有错误**：PP 仍把“中國蒜苗”漏成“中國苗”、把“黃燈籠”读成“黃燈龍”。不能将中文改善理解为全部中文可靠。
- **商户 Logo**：PP 经常漏掉 Costco 标志，只留下 WHOLESALE 或错误变体；H MART 丢失 H。这是完整票据通过率低的重要原因。
- **重量单位**：PP 多次将 `lb` 读成 `1b`。现有结构化和规则未稳定恢复，部分商品丢失实际称重，或把 `(1POUNDS)` 包装描述当成重量。没有为了让 PP 通过而临时修正这些字符。
- **长收据与总额**：391b3273 的 subtotal/tax 标题在 PP 中有错字，仍出现 `26/18`，最终多出错误行且总额未确定。
- **退款**：会员退款金额在两边都保留负数；PP 的商品退款票出现额外行、总额未确定。负数识别必须与结果结构一起看。
- **新增优惠票**：00c86447 两边都把部分负优惠标成 deposit；00710190 两边都未正确拆分花生的包装优惠。这些是需要独立修复的结构化/业务规则问题，不能期待换 OCR 自动解决。
- **失败样本**：Unlimited 的 a730a1be 原始 OCR 成功，但 Qwen 结构化达到输出限制，返回 `incomplete_output`。PP 本次 17 张都完成结构化，但仍有字段差异。

## 运行条件与验证

Unlimited 使用现有 RTX 5090 GPU 服务；PP 为 CPU、8 线程，以保留 playground 的 GPU 服务和两容器结构。原始采集中位耗时约 8.1 秒和 30.0 秒，**不能将不同硬件的耗时当成模型速度排名**。模型切换部署前仍需在同一硬件上比较性能。

离线 Rust 测试 69 项通过；Python 测试 6 项通过；Clippy 通过。两次模型质量门禁如实返回失败，完整报告已保存。临时结构化代理已停止，原有两个 playground 容器保留运行，未修改用户票据、Alias 或客户端。

人工标注复核纠正了旧 a730a1be 的“蒜苔”为照片上的“蒜苗”；对于新增一处难以确认的中文品牌字明确只评分可见片段。旧 12 张历史基线及其原标注哈希仍保留。

## 后续建议

保留 Unlimited-OCR 为当前主识别。优先修复两边共有的优惠/商品行关联问题，再试验 PP 对中文商品名的补充识别，以及有原图证据和算术校验的重量单位恢复。混合方案必须重新通过这 17 张测试后再考虑上线；本次结果不能直接证明混合方案有效。
