# 商店类别：与商品分类平行的消费维度

## 已确认的规则

- 每条消费有一个商店类别，同时仍只有一个商品分类，两者独立。
- 同名瓶装水在餐馆购买属于餐馆，在杂货店购买属于杂货；不修改该商品的其他历史消费。
- 商店类别预置杂货、餐馆、旅行，允许新增（例如网购）、改名、删除。未分类是受保护的真实类别记录。
- 商店保存默认商店类别。识别 Logo/名称后，后端根据商店填充本次收据与明细的类别。未知商店保持未分类，由用户设置商店默认值。
- 商品分类、名称映射继续共用既有目录。草稿不新增商品目录记录，编辑保持在客户端，只在明确保存时提交。
- 编辑商店类别应用到所有当前明细；明细也可单独修改。更改商店默认值仅影响后续识别，不改变已保存的历史分类。

## 数据结构与 API

Schema version 16，保持第三范式。`receipt_type` 存唯一名称；`merchant_receipt_type` 存商店默认值；`receipt_type_assignment` 存本次收据默认值；`line_receipt_type_assignment` 只存与收据默认值不同的明细覆盖值。`line_effective_receipt_type` 解析实际类别。商品名称不保存全局商店类别。

- `receipt_types/list|save|delete` 管理类别；`merchants/list|classify` 管理商店默认值。
- 收据及明细 JSON 使用 `receiptTypeId`。已发布旧客户端/已有识别任务遗漏字段时保留现有分类；明确 null 的明细继承商店类别。
- 类别名称按现有目录规范规范化、忽略 ASCII 大小写且唯一。删除类别解除关联并设为未分类，保留收据、明细与照片。目录写入使用事务与版本冲突检查。
- `reports/summary|details|trend` 接收可选 `receipt_type`，与 `category` 筛选同时使用。
- 报表提供 `receipt_type` 分组与独立趋势曲线，包括零消费不可选类别。每次从当前 SQLite 查询，不缓存统计快照。退款/折扣保持有符号金额，沿用交易日汇率统一报告币种。
- 商店类别合计包含其收据层面的已确认差额及逐项汇率舍入差（返回 `reconciliation`），不新增平账商品，不分摊到商品分类。

## 客户端

Web 和共享 Android/iOS 代码提供收据/明细类别编辑、“商店”页面下的“商店名称”和“商店类别” tabs、商店默认值、报表类别范围与分组、独立类别趋势与图例。报表点击商店类别进入该范围的商品分类。保留图表在周期/曲线控件上方、商品曲线默认折叠等现有交互。

## 现有数据：一次性离线更新

不增加服务启动迁移。新库直接初始化 version 16；旧 version 15 必须停 API 后执行：

```sh
python3 src/backend_api/tools/add_receipt_types.py \
  --data-dir /absolute/backend_api-data \
  --backup-dir /absolute/unique-receipt-types-backup
```

脚本从 canonical `schema.sql` 读取新增结构，预检主数据库和所有用户数据库，先备份全部待更新库，再更新。原应用只支持杂货，因此现有商店和收据归为杂货；已有表的逻辑数据、照片关联和认证数据库保持原样。重复执行已更新的库无操作。新 image 应在所有业务库完成更新后启动；身份数据库无需改动。

现有 `/data/prompt.toml` 是用户配置。升级识别能力只替换匹配到的通用提示片段，保留所有商店专用提示词；不要用镜像模板覆盖整个用户文件。

## 验证

后端覆盖跨场景同名商品、商店默认值、明细覆盖、旧客户端字段遗漏、分类唯一性、删除与外键、分组/筛选/趋势和识别数据转换；离线工具覆盖所有用户命名空间、备份、完整数据保留与重复执行。客户端验证类别筛选、曲线图例和商店分类独立于商品分类，继续运行现有编辑/报表回归检查。

## 商店目录与残留清理

商店管理只列出有已命名 Logo 样本的商店。手动录入的商店文字仍可保留在收据中，但不会自动进入 Logo 商店目录。删除收据或修改 Logo 名称后，后端清理没有 Logo、没有收据关联、没有在用 SKU 的商店及其孤立地址、别名和 SKU。历史残留可停服务后运行 `src/backend_api/tools/prune_unused_merchants.py`，先备份再清理；不修改收据、明细或照片。显示名称全局统一为“商店类别”；现有 `receipt_type` 存储/API 契约保留，因为类别依旧落实在每次消费上。
