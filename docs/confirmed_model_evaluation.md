# 全部已确认收据：8B 与 32B 实测

2026-09-16（纽约；UTC 2026-09-17）。结论：此次 32B AWQ 配置没有改善整体结果，playground 恢复使用 8B BF16。32B 镜像保留为 `receipt-master-backend-ocr:32b-evaluated`。

## 数据和方法

通过只读 API 冻结当时数据库全部 **24 张已确认、未删除的收据及其 24 张照片**，不挑选成功样本。另有 4 张草稿不在本次范围。店铺包括 Costco 10、SkyFoods 7、H Mart 3、99 Ranch 2、Feilong 1、Target 1。

以用户保存的确认数据为预期值。两模型使用相同照片、vision-v7 通用/店铺提示词、JSON Schema、生产校验和单位/金额转换，最多两次尝试。仅把已确认店名、国家、币种作为上下文，不把商品答案提供给模型。本轮评估商品提取，不重新评估 Logo 匹配。

逐项比较票面名称、种类、金额、票面净额、折扣关联、已知 SKU/税码/数量/单价/重量/单位，以及币种和交易时间。用户自定义商品名称、分类、未知字段不计分；同名商品一对一匹配并考虑已知元数据，不因数组重排直接判错。

23 张缺少历史任务时区，明确使用 America/New_York；1 张沿用任务记录的同一时区。数据库 UTC 不变。所有原始收据和照片不被测试覆盖；生产解码在临时数据库中完成。

## 结果

| 指标（每项分母均为 24） | 8B BF16 | 32B AWQ |
| --- | ---: | ---: |
| 返回通过校验的结果 | 19/24 | 12/24 |
| 总金额与确认数据一致 | 18/24 | 11/24 |
| 明细行数一致 | 12/24 | 7/24 |
| 全部比较字段一致 | 2/24 | 1/24 |
| 单张请求耗时中位数（含重试/排队） | 21.48 秒 | 54.45 秒 |
| 整批实际耗时（并发 2） | 385.00 秒 | 766.12 秒 |

严格通过率不是文字字符准确率，也不是人工重新标注的绝对正确率：保存的数据包含过去确认的数量、默认单价等。本次忠实按用户确认值计分，没有为了提高分数修改答案。HTTP 失败在各项都计为未通过。

32B 日志多次出现 `Invalid image evidence reference or box`，触发重试；因此失败包含证据框结构错误，并非都没有读出文字。评测器未保存最终 HTTP 错误体，不能把每个失败都归因于坐标。有效结果仍存在年份、数量、折扣、SKU 和多余行等差异。

例如 `4e491343` 的日期错误被 32B 修正，`e6c62f11` 的差异由 36 处降为 21 处；但多张 8B 能返回的收据在 32B 下请求失败，整体没有改善。

## 配置与边界

- 8B：官方 Qwen3-VL-8B-Instruct，BF16 权重及 KV cache。
- 32B：QuantTrio/Qwen3-VL-32B-Instruct-AWQ，4-bit AWQ 权重、BF16 激活、FP8 KV cache，没有提供校准 KV scales。
- 单张 RTX 5090 32GB；相同 vLLM 版本、32K 上下文、图片分辨率上限和并发数。32B memory_fraction 为 0.83，8B 为 0.80。32B 实测整卡显存约 31.9GB，余量很小；本轮未观察到推理 OOM。
- 固定模型 revision、镜像 ID、提示词 SHA256 和详细参数见归档。此结论只适用于本次量化/缓存/提示词组合，不能推断全精度 32B 或所有大模型都更差。
- 本批每张收据只有一张保存照片，不能据此宣称验证了所有多图长收据情形。

模型来源：[官方 32B](https://huggingface.co/Qwen/Qwen3-VL-32B-Instruct)、[本次 AWQ 权重](https://huggingface.co/QuantTrio/Qwen3-VL-32B-Instruct-AWQ)。

## 重现与验证

快照与照片：[confirmed/2026-09-17](../tests/backend_api/corpus/confirmed/2026-09-17/snapshot.json)。完整输出、配置、32B Dockerfile、部署信息和汇总：[评测归档](../tests/backend_api/corpus/baselines/2026-09-17-confirmed-models/deployment.json)。操作步骤：[corpus README](../tests/backend_api/corpus/README.md)。

快照采集器会读取全部分页、检查照片哈希及采集期间数据是否变化。后续新增确认收据时重新生成新目录，旧快照保持可重复对比。离线评分可重用保存的模型输出，不必再次运行 GPU。

常规回归 79 项 Rust 测试、4 项 OCR Python 测试及 Docker/Android 合并构建通过。真实模型精度测试因上述不匹配返回失败，不能把构建通过当成识别验收通过。原生 iOS 未在 Linux 编译。

恢复后的 8B 两个容器均健康；两张重叠照片的异步任务通过，自动生成草稿、商品去重、总额 USD 14.00、查询响应及 APK 10025 下载哈希检查均通过，测试草稿已清理。再次只读采集核对，原 24 张确认记录、版本和照片哈希均未变化。
